# 按材料定位事实

## 仓库

先读适用指令、README、分支及工作区状态；按本次项目范围定位入口、关键实现和测试，不扫描所有磁盘项目。保留已有改动。记录查看的版本；未提交内容与已发布版本分开。

用最短证据链说明功能：需求/触发 → 入口 → 核心模块 → 数据或外部接口 → 输出与验证。文件/符号在实际源码中定位；异步调用需要消费者或注册证据，不能仅根据函数名补全链路。

README 与代码冲突时，对实现以代码为准并说明差异；生产是否启用仍需部署或运行证据。先检查脚本入口和副作用；写作不要求启动后台服务、改数据库、调用付费模型或发送消息。

## 工作记录与聊天

仅给聊天即可自动整理的入口、分页与长文件读取、消息归属及默认交付见 [聊天到简历信息](chat-to-resume.md)。

用户指定的聊天先实际读取，再引用其中的职责确认、决策和运行结果。助手给出的完成宣告只能作为线索；支持“已验证”的表述还要找到相应结果或用户确认，并保留来源性质。

按项目与时间归并需求、修复、发布、验证和反馈。聊天中的拟实施方案、失败后推测和未完成任务不进入已完成经历。历史测试记录标明版本/日期，本轮没有执行就不写成当前通过。

## 文档与截图

设计稿支持需求与方案，验收记录支持其中明确的验收范围。截图只能说明看见的状态；打不开、缺页或 OCR 不可靠时保留解析边界，不把未提取到的事实判成没有做过。

优先本地文本提取；需要外部 OCR 或模型时按本次材料授权执行。只读查看原文件，生成简历或笔记时使用副本。

## 飞书等在线材料

只有用户提供并要求使用时读取。现有可用 CLI/API 优先；飞书优先 lark-cli，先核对本机 help，再按当前 URL 解析范围、查询实际字段及记录，不沿用历史表/身份。

只读取任务必要字段与附件；实际返回的附件标识或文档地址用于下载/读取，不猜 URL。检查视图范围与分页。下载到私有目录，命名避免真实个人信息；源码、记录 ID、内部链接与简历原文不公开。

他人简历只能用于观察表达结构，不能搬用其项目、数字或职责。读取不包含创建记录、写评价或更改招聘状态的授权。
