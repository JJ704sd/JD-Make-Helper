# 项目证据复盘

用于只复盘项目、AI 编程对话或交付状态的请求。复盘可成为后续简历的事实基线；用户未要求简历时，不生成候选简历段落，也不启动文件制作。

## 读取与归并

聊天引用、导出与后续修正按 [聊天读取流程](chat-to-resume.md)处理；源码与文档按 [材料定位](material-input.md)读取。归并同一业务目标的连续记录，保留来源覆盖、未读附件与最终状态。用户不需要先填项目卡。

按 [证据与归属](evidence-and-ownership.md)判断个人动作、指标口径与验证范围；复盘不改变事实的确认条件。

## 让结论能回到材料

每个项目按材料组织以下信息，可合并成连贯段落，不要求填满固定章节：

| 信息 | 应能回答 |
|---|---|
| 问题背景 | 谁遇到了什么问题，有什么约束？ |
| 方案与取舍 | 采用了什么、为何采用、哪些方案仅评估未实施？ |
| 本人动作 | 本人设计、实现、审查、调试或验证了哪里？团队、AI、平台分别做了什么？ |
| 交付阶段 | 材料支持计划、已实现、原型验证、内部试点还是生产使用？ |
| 实际范围 | 在什么环境、版本、输入、用户范围与时间内成立？ |
| 结果依据 | 是实测结果、阶段交付、技术验证还是估算收益？ |
| 责任边界 | 哪些确实由本人负责，哪些只是参与、接入或未负责？ |
| 待补证据 | 缺少哪些会改变结论的材料或确认？ |
| 可展开的追问 | 哪些技术机制、失败路径或取舍已有依据可解释？ |

交付阶段与结果性质分别描述：试点也可能有实测数据，代码实现也可能没有运行记录。没有环境或使用记录时保留未知，不沿着“有代码 → 有测试 → 已上线”自动升级。

后续失败、回滚或用户否认限制此前结论；先保留有依据的历史结果，再说明最终范围。冲突没有解决时不选择更好看的版本。

## 输出与交接

短复盘直接交付证据摘要、材料覆盖与关键待补项。长记录、跨项目或用户需要复用时，在私有目录保存 evidence-recap.md 与沿用的 claim-ledger.md；已有账本更新同一事实 ID。内部原文与定位留在私有材料，对外摘要泛化未公开标识。

同时要求简历时，以可采用事实继续提炼；同时要求岗位分析时，以同一账本进入 [JD 对照](jd-matching.md)。只复盘时，到证据摘要为止。待补清单不是用户必须重新填写的全量表单。
